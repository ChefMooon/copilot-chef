# Phosphor Icon System Upgrade

## Plan Status

- Status: ready after revisions
- Confidence: high
- Owner: renderer visual system and route component owners
- Source of truth: `docs/copilot-chef-style-guide.md` for renderer visual conventions

## Goal

Make `@phosphor-icons/react` the renderer UI icon standard across the shared
shell and product routes while preserving workflows, visible labels, computed
accessible names, user-entered persona emoji, data visualization marks, QR
output, and packaged branding.

The update includes a bounded button affordance and accessibility audit. It
does not introduce a generic rendered control-tooltip primitive in this phase.

## Scope

### In scope

- UI-facing icons across the shared shell and all routes in the established QA order
- Existing Lucide imports, inline UI SVG, CSS-drawn UI marks, Unicode symbols, and app-authored UI emoji
- A narrow shared icon wrapper for visual defaults only
- Typed renderer-side semantic icon mappings for data-driven Grocery and Prep filters
- Accessible-name, label, focus, hit-area, spacing, and disabled-state review for touched controls
- Focused renderer tests, browser route validation, Electron shell smoke validation, and style-guide deltas

### Out of scope

- Backend behavior, API contracts, persistence, and database changes
- Recharts tooltips, heatmap cells, chart marks, data dots, meal-type dots, and color swatches
- QR-code SVG output generated by `qrcode`
- User-entered persona emoji and persona text content
- `resources/icon.png` and other packaged Electron or installer branding assets
- Typography, palette, workflow, and product-copy redesign
- A generic rendered tooltip primitive for controls

## Resolved Decisions

- Use `@phosphor-icons/react`; remove `lucide-react` after all renderer call sites are migrated.
- Use a narrow shared wrapper in `src/renderer/components/ui/` for repeated visual defaults. Keep accessibility semantics at the calling control and use direct Phosphor imports for one-off icons when the wrapper would obscure intent.
- Use regular weight for standard navigation and dense controls. Use bold for selected, favourite, and destructive state emphasis.
- Keep visible labels and existing accessible names. Decorative child icons use `aria-hidden="true"` and must not become a second accessible name.
- Store stable semantic icon keys, not React components or presentation glyphs, in `src/renderer/lib/grocery.ts` and `src/renderer/lib/prep-lists.ts`. Resolve them through a typed registry at the renderer boundary.
- Defer rendered control tooltips. Audit accessible names and supplemental native `title` usage now; no workflow may depend on hover, focus-triggered tooltip text, or touch tooltip behavior.
- Keep the established browser QA route order for validation. Add a separate Electron smoke check for Electron-only shell behavior.

## Review Revisions

The original assessment required these changes before implementation:

- Reframe C3 from a possible shared tooltip implementation into an accessible-name and affordance audit. A future tooltip primitive would need explicit contracts for hover, keyboard focus, touch, dismissal, layering, overflow, and modal behavior.
- Make computed accessible names the test contract. The current QA helper checks `aria-label` and `placeholder` attributes but does not prove the browser's computed role/name result. Title-only controls must receive stable names where needed.
- Add Electron validation. Browser QA is explicitly browser-only, while the app shell owns Electron-only window controls, platform sizing, drag regions, and behavior.
- Add an authoritative source inventory and live-call-site check. `PersonaGrid` currently appears unused; treat it as legacy unless the inventory finds a consumer. Keep `PersonaModal` emoji input unchanged as user content.
- Treat C2 as a documentation delta. The style guide already contains most of the Phosphor target, sizing, `currentColor`, accessibility, exception, semantic-key, and route-order guidance.
- Add focused tests for icon-bearing states that current tests do not render, including RecipeCard optional actions, Grocery/Prep quick filters, and title-only list controls.

## Revised Implementation Plan

### Phase 0: Baseline and authoritative inventory

1. Run the existing focused/full test baseline and lint where available. If bundle size will be reported, capture a pre-migration `npm run analyze:bundle` result.
2. Scan `src/renderer` for Lucide imports, inline UI SVG, CSS pseudo-element marks, Unicode symbols, app-authored emoji, `title` attributes, and icon-only controls.
3. Verify live call sites for every named surface. Classify each result as a UI icon, user content, data visualization, QR output, or packaged-branding exception.
4. Record a checked migration list by component owner. Flag title-only controls that need stable accessible names, and treat `PersonaGrid` as legacy unless a live consumer is found.

### Phase 1: Lock the renderer icon contract

5. Add `@phosphor-icons/react` with npm so `package.json` and `package-lock.json` remain synchronized.
6. Add the narrow shared wrapper under `src/renderer/components/ui/`. Its contract should cover stable size defaults, regular default weight, `currentColor`, class/ref forwarding, and visual defaults only. It must not hide or invent caller-owned accessibility semantics.
7. Add the typed renderer-side semantic icon registry for Grocery and Prep filter keys. Replace presentation emoji in the domain modules with stable keys, map keys to Phosphor components in renderer code, and test that every declared key resolves.
8. Keep icon-only controls named by their parent `aria-label` or equivalent visible text. Mark decorative child icons `aria-hidden="true"`. Use bold only for selected, favourite, and destructive state emphasis.

### Phase 2: Representative spike and focused gate

9. Migrate a representative slice: AppShell Settings/window controls, one Meal Plan period or action control, one Grocery quick filter, and RecipeCard favourite/edit/delete actions.
10. Preserve CSS hit areas, focus rings, drag regions, disabled states, print-hidden behavior, platform branches, and Electron IPC behavior.
11. Update the shell test to assert semantic links/buttons and decorative icon behavior instead of the gear glyph text. Add focused coverage for wrapper defaults, registry completeness, QuickReference, ItemRow/ListEditor title-only actions, and RecipeCard optional callbacks.
12. Run the focused Vitest tests and `npm run build:web` immediately after the spike. Inspect the same slice at desktop and narrow widths in light, dark, and custom-theme states.
13. Stop and revise the contract if the spike changes accessible names, baseline alignment, hit areas, focus behavior, theme inheritance, or build output unexpectedly.

### Phase 3: Route-owner migration and C3 audit

14. After the spike passes, migrate remaining UI marks in owner batches: shared shell; Meal Plan; Grocery and Prep; Recipes; Home and Settings; then remaining Connect and Stats controls.
15. Use the browser QA route order for validation, not as a reason to duplicate icon definitions.
16. Keep charts, heatmaps, Recharts tooltips, data dots, swatches, QR SVG, persona emoji, and packaged assets unchanged. Replace CSS-drawn window marks and inline action SVG only when the inventory classifies them as UI icons.
17. Audit buttons and button-like links during each batch. Visible-label controls keep their labels and do not receive redundant tooltip work. Icon-only or unfamiliar controls must have stable accessible names and appropriate hit areas. Native `title` may supplement pointer discovery but is never the sole name or a keyboard/touch dependency.
18. Do not introduce a generic rendered control-tooltip primitive in this phase. Keep heatmap and chart tooltip behavior separate.
19. Remove `lucide-react` only after a scoped source search confirms that no renderer imports remain. Verify package and lockfile state afterward.

### Phase 4: Documentation and release validation

20. Update only the delta in `docs/copilot-chef-style-guide.md`: the exact weight policy, wrapper responsibility, semantic registry boundary, deferred-tooltip policy, and final exception inventory. Do not claim completion before the source inventory and tests pass.
21. Run focused renderer tests, the full `npm run test`, `npm run lint`, `npm run build:web`, and `npm run build`.
22. On Windows, stop active Electron processes before Prisma-backed builds if the query-engine DLL is locked. Use the repository's documented no-engine workaround only when the lock makes it necessary.
23. Rebuild the web bundle before browser evidence. Execute the route matrix in order at desktop and narrow widths, including light, dark, and custom themes. Record visual, keyboard, accessible-name, title-policy, and functional findings.
24. Run an Electron smoke check with the documented development or packaged/unpacked flow. Verify custom window controls, platform branches, drag-region behavior, hash routing, and migrated shell icons. If bundle size matters, run the post-migration `npm run analyze:bundle` and compare it with the baseline.

## Acceptance and Verification

- `@phosphor-icons/react` is the renderer UI icon dependency and no renderer Lucide imports remain. Verify with a scoped source search and package/lockfile inspection.
- Every inventory item is classified, and live call sites are covered. Unresolved raw UI marks fail the gate unless explicitly recorded as exceptions.
- Every touched icon-only or unfamiliar control has a stable computed accessible name independent of `title` or any future tooltip. Verify with Testing Library `getByRole` name assertions and revised QA helper coverage.
- Decorative icons are hidden from the accessibility tree and do not duplicate parent names. Verify in wrapper and representative component tests.
- Grocery and Prep data modules contain semantic keys only, and every key resolves in the renderer registry. Verify with TypeScript checks and mapping completeness tests.
- Visible labels, click behavior, drag/drop behavior, disabled states, focus rings, hit areas, print-hidden behavior, and theme token inheritance are preserved. Verify with focused component tests and the route matrix.
- Browser validation covers `/connect`, `/`, `/meal-plan`, `/recipes`, `/recipes/:recipeId`, `/grocery-list`, `/grocery-list/shop/:id`, `/prep-lists`, `/prep-lists/prep/:id`, `/stats`, and `/settings` at desktop and narrow widths in light, dark, and custom themes. Verify only after `npm run build:web`.
- Electron shell controls render only in Electron and invoke the correct platform methods; browser mode does not render them. Verify with shell tests and an Electron smoke run.
- No workflow depends on a rendered tooltip or native `title`. Verify through focused audits and keyboard/touch review.
- Any bundle-size claim is supported by pre/post `npm run analyze:bundle` evidence rather than an assumption about removing Lucide.

## Open Decisions

There are no blocking decisions. The implementation contract is resolved as follows:

- Rendered control tooltips are deferred.
- A narrow visual icon wrapper is used alongside a typed renderer registry.
- Regular is the default Phosphor weight; bold is reserved for selected, favourite, and destructive emphasis.
- Exact one-to-one icon mappings for app-authored culinary accents are selected during the inventory and representative spike, then recorded as implementation details or explicit exceptions.

## Handoff

This plan is ready for implementation. The Phosphor migration remains bounded
to renderer UI concerns, while the revised C3 scope protects accessible names
and control affordances without introducing an unowned tooltip system. Browser
and Electron validation are separate required surfaces, and the documented
exceptions remain outside the migration.
